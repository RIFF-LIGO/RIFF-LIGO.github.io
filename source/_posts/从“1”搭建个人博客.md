<h1 id="EgdfQ">搭建博客的初衷</h1>
<h2 id="H9Euz">📌我搭建博客的原因：</h2>
某一天，为了解决某个问题，用搜索引擎去找办法，于是搜到了别人的博客里面的一篇文章，发现这个博客的样式很炫酷✨。然后就开始了我自己搭建博客的历程。

<h2 id="iq4kq">💡为什么要分享呢？</h2>
搭建完博客，总不能让它空有外壳吧，于是我开始每学一个新东西都开始记笔记（其实在这之前我从来都不写笔记，也不爱写东西💤），一步步把博客填充了一些内容。然后其实会发现能够更好的看清楚自己，也提高了一些写文档的能力。

所以我想，在这个信息爆炸的时代，我们每天都会接触到大量的信息，但这些信息往往在我们的脑海里停留不了多久。或许真正有价值的是能够把自己表达出来，比如刚学会了一个超级炫酷的新技能，或者灵光一闪解决了个很难的问题，甚至是看了一场电影后心里泛起的小波澜……而这些东西都可以通过写博客的方式记录下来。这些看起来不起眼的记录，随着时间的推移，会变得越来越珍贵。它们不仅能够帮助我更好地认识自己，或许也能够解决别人的某个问题。

<h1 id="YBMjs">hexo 是何物</h1>
💡**相关文档**：[官方文档](https://hexo.io/zh-cn/docs/)

💡**环境：**node.js 12.0 及以上版本、git

💡**基本介绍：**hexo 是一个<font style="background-color:#D9EAFC;">基于 Node.js 的快速、简洁且强大的静态博客框架</font>，它通过将 Markdown 文章转换为静态网页（HTML、CSS、JS 等），帮助用户轻松搭建个人博客或文档站点，无需依赖数据库或后端服务器（更适合前端同学的体质🤸）。

<h2 id="wJkBH">📌创建项目三步曲</h2>
1️⃣安装 hexo ： npm install -g hexo-cli (全局安装 hexo)

2️⃣初始化项目：

    - hexo init <folder> （创建项目，本质上就是 clone 了 hexo 官方的一个 git 仓库）
    - cd <folder>
    - npm i （安装依赖）

3️⃣启动项目：hexo server

<h2 id="UiHUD">📌创建与发布文章</h2>
<h3 id="zUpZM">🚩Front-matter</h3>
**描述：**<font style="color:rgb(68, 68, 68);">Front-matter 是文件开头的 YAML 或 JSON 代码块，</font><font style="color:rgb(68, 68, 68);background-color:#D9EAFC;">用于配置写作设置</font><font style="color:rgb(68, 68, 68);">。 以 YAML 格式书写时，Front-matter 以三个破折号结束；以 JSON 格式书写时，Front-matter 以三个分号结束。</font>

> tips：写作配置：比如说该文章的布局、标题、建立时间、
>

** 格式： **在 .md 文档中和 YAML 格式一致，以三个<font style="color:rgb(68, 68, 68);">破折号开头和结束</font>如下：

```markdown
---
<!-- 标题 -->
title: Hello World
<!-- 时间 -->
date: 2013/7/13 20:46:25
<!-- 更新时间 -->
updated:
<!-- 布局 -->
layout:
<!-- 是否开启评论 -->
comments:
<!-- 标签 -->
tags:
<!-- 分类 -->
categories:
<!-- 是否发布 -->
published:
---
```

<h3 id="m00hO">🚩创建&发布</h3>
1️⃣ 执行命令来创建一篇文章：hexo new [layout] title

> tips: layout 是布局，默认是 post ，为可选参数，title 就是文章的标题，为必选参数
>
> 布局一般有三种方式：post、page 和 draft。 每个布局创建的文件会被保存到不同的路径
>

2️⃣ 新建文章时，会根据 scaffolds 文件夹内相对应的模板来创建文件且新建文章在，比如说当你 hexo new post  "test" 就会创建一个 test.md 在 source 的 _post 目录下。如下图：

![](https://cdn.nlark.com/yuque/0/2025/png/55336718/1763192946361-c8b9b2a7-c7ff-4d2f-b453-2b21ebc5db8b.png)

编写完后就可以在 localhost 下看到对应的文章了，如下：

![](https://cdn.nlark.com/yuque/0/2025/png/55336718/1763193562339-3819bfa8-7ac5-4b99-86e1-9ac2b6e83470.png)

 

3️⃣ 有一个特殊的布局，草稿布局 draft ，可以创建一个草稿，用 hexo new draft title 命令，这样创建出来的草稿会在 source/_draft 目录下。这样创建出来的草稿，是不可见的，可以通过发布命令： hexo publish [layout] title 把草稿移动到_post 文件夹，这样就发布出来，可以在网页上看到。

> tips：其实hexo new post/page/draft title 可以做简化，简化为 hexo n post/page/draft title 。
>

<h2 id="GeU9v">📌引入 butterfly 主题</h2>
1️⃣ 在 hexo 根目录拉取 butterfly 仓库：

```markdown
git clone -b master https://github.com/jerryc127/hexo-theme-butterfly.git themes/butterfly
```

2️⃣ 修改_config.yml 的 theme 字段为 <font style="background-color:#D9EAFC;">butterfly。</font>

3️⃣ 安装 pug 和 stylus 的渲染器。

```markdown
npm install hexo-renderer-pug hexo-renderer-stylus --save
```

4️⃣ 重新启动服务 hexo server 就可以看到主题样式生效了，如下图：

![](https://cdn.nlark.com/yuque/0/2025/png/55336718/1763257628813-7e5b9a2b-9229-4f2e-a24a-4875c7a2446a.png)

5️⃣ 主题目录如下：

![](https://cdn.nlark.com/yuque/0/2025/png/55336718/1763257835827-d305f259-f8dc-4966-8382-3493504f9eb9.png)

其中常用的目录为 source 下的 img 用于存放一些背景图片，404 图片，头像图片，网站图片等静态图片。另外 themes/butterfly/_config.yml 是主题的配置，用于配置多个目录，网站背景、网站 tab 图片、分类 menu 等。

<h1 id="ZgY4A">部署到 github Pages</h1>
🔍**什么是 github Pages：**

GitHub Pages 是 GitHub 提供的一项免费静态网站托管服务，允许你直接从 Git 仓库发布静态页面（HTML/CSS/JS），常用于个人/项目博客、文档或演示站点。

<h2 id="kRob4">📌简单部署<font style="background-color:#D9EAFC;"></font></h2>
1️⃣ 首先下载插件<font style="color:#81BBF8;"> </font><font style="color:#000000;background-color:#D9EAFC;">hexo-deployer-git</font><font style="color:#81BBF8;"> </font>：

```javascript
npm i hexo-deployer-git
```

2️⃣ 在 github 上创建一个新的仓库，命名为用户名.github.io，比如：

```javascript
deploy:
  type: git
  repo: https://github.com/<username>/<project> #github仓库地址
  # example, https://github.com/hexojs/hexojs.github.io

```

**弊端**

💥这种方式可以快速的部署基本完成一个博客，但是它本质上是通过插件在本地生成静态页面后仅仅将静态页面部署到了 github 上去托管。所以有弊端，这种方式部署后，由于在 github 远程仓库里的只是静态文件而不是源文件，就只能在一台设备上写。

<h2 id="nVQcR">📌CI/CD工作流部署</h2>
🔍**这种部署方式的区别是什么：**

简单来说就是通过配置文件配置一个工作流，让原本需要在本地运行命令构建的步骤在 github 上自动去执行，从而每次只需要 git add 、git commit 、git push 即可发布文章。

💡具体步骤

1️⃣ 在.github 目录下创建 workflows 文件夹，里面创建 deploy.yml 的配置文件作为工作流配置文件、配置文件以及含义如下：

```yaml
# 工作流的名称，会在 GitHub Actions 界面显示
name: Deploy ks blog

# 定义触发工作流的事件
on:
  # 当有代码推送时触发
  push:
    # 指定触发分支，只有推送到 master 分支时才触发
    branches:
      - master

# 定义工作流中的任务
jobs:
  # 任务名称：构建和部署
  build-and-deploy:
    # 指定任务运行的环境：最新版本的 Ubuntu 系统
    runs-on: ubuntu-latest
    # 任务的显示名称
    name: Build and deploy Hexo Site

    # 定义任务中的执行步骤
    steps:
    # 步骤1：检出源代码
    - name: Checkout source code
      # 使用官方 checkout Action 来获取仓库代码
      uses: actions/checkout@v4

    # 步骤2：设置 Node.js 环境
    - name: Setup Node.js
      # 使用官方 setup-node Action 来配置 Node.js
      uses: actions/setup-node@v4
      with:
        # 指定 Node.js 版本为 20
        node-version: '20'

    # 步骤3：全局安装 Hexo 命令行工具
    - name: Install Hexo CLI Tools
      run: npm install -g hexo-cli

    # 步骤4：设置 NPM 缓存以加速后续构建
    - name: Cache node modules
      # 使用 cache Action 来缓存 node_modules
      uses: actions/cache@v4
      # 为此步骤设置 ID，便于后续步骤引用
      id: cache
      with:
        # 缓存路径：用户主目录下的 .npm 文件夹
        path: ~/.npm
        # 缓存键：基于系统环境和 package-lock.json 的哈希值
        key: ${{ runner.os }}-node-${{ hashFiles('**/package-lock.json') }}
        # 备用缓存键：当精确匹配失败时使用
        restore-keys: |
          ${{ runner.os }}-node-

    # 步骤5：配置 SSH 私钥用于服务器连接
    - name: SSH Key Setups
      run: |
        # 创建 .ssh 目录（如果不存在）
        mkdir -p ~/.ssh
        # 将保存在 GitHub Secrets 中的 SSH 私钥写入文件
        echo "${{ secrets.SSH_PRIVATE_KEY }}" > ~/.ssh/id_ed25519_ks
        # 设置私钥文件权限为仅当前用户可读
        chmod 600 ~/.ssh/id_ed25519_ks

    # 步骤6：注册服务器 SSH 指纹以避免交互式确认
    - name: SSH Fingerprint Registration
      run: |
        # 创建 known_hosts 文件（如果不存在）
        touch ~/.ssh/known_hosts
        # 设置文件权限
        chmod 600 ~/.ssh/known_hosts
        # 将服务器指纹添加到已知主机列表
        echo "${{ secrets.SSH_FINGERPRINT }}" >> ~/.ssh/known_hosts

    # 步骤7：安装项目依赖
    - name: Install dependencies
      # 使用 npm ci 而不是 npm install，因为它更适合 CI/CD 环境
      # npm ci 会严格根据 package-lock.json 安装依赖，确保环境一致性
      run: npm ci

    # 步骤8：生成 Hexo 静态文件
    - name: Generate static files
      # 执行 Hexo 生成命令，将 Markdown 转换为 HTML 等静态文件
      run: hexo generate

    # 步骤9：配置 Git 用户信息用于后续的提交操作
    - name: Set Bot Info for Git
      run: |
        # 设置全局 Git 邮箱
        git config --global user.email "3074512953@qq.com"
        # 设置全局 Git 用户名
        git config --global user.name "ks-high"

    # 步骤10：配置部署目标服务器信息
    - name: Set Deploy Target
      run: |
        # 使用 sed 命令替换 _config.yml 中的占位符为实际的服务器主机地址
        sed -i "s#\${SSH_GIT_HOST}#$SSH_GIT_HOST#g" _config.yml
        # 使用 sed 命令替换 _config.yml 中的占位符为实际的部署文件夹路径
        sed -i "s#\${GIT_FOLDER}#$GIT_FOLDER#g" _config.yml
      env:
        # 从 GitHub Secrets 获取 SSH 服务器主机地址
        SSH_GIT_HOST: ${{ secrets.SSH_GIT_HOST }}
        # 从 GitHub Secrets 获取部署目标文件夹路径
        GIT_FOLDER: ${{ secrets.GIT_FOLDER }}

    # 步骤11：执行部署到服务器
    - name: Deploy to Server
      # 执行 Hexo 部署命令，这会通过 SSH 将静态文件部署到目标服务器
      run: hexo deploy
```
